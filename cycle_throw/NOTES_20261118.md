# 2026-11-18 cycle-throw 통합 작업 정리 (Claude Code)

팀원의 grasp-and-throw 사이클 플래너(`grasp_and_throw_20261116`)를 gp8_control 에 붙이면서 이 PC 에 한 일을 적는다.
**실기에서 cycle 모드는 아직 한 번도 돌리지 않았다.**

## 1. 이 PC 에서 바꾼 것

### (1) 드라이버를 500 Hz 설정으로 변경 — `~/Desktop/motoman_ros2_safety_review/motoman_ROS2`
| 파일 | 변경 | 백업 |
|---|---|---|
| `motoman_bringup/config/controllers.yaml` | `update_rate: 250` → `500` | `controllers.yaml.bak_250hz_20261118` |
| `motoman_description/robots/ros2_control.xacro` | `<hardware>` 에 `control_period 0.002`, `limit_fault_cycles 10`, `limit_decel_cycles 50` 추가 (리미터 감지 20 ms · 감속 100 ms 를 500 Hz 에서도 유지) | `ros2_control.xacro.bak_250hz_20261118` |

- 두 패키지를 다시 빌드했다: `colcon build --packages-select motoman_bringup motoman_description`.
- 팀원(ryugaeun)도 이 드라이버 설치본을 underlay 로 source 한다. `motoman_bringup` 은 팀원 overlay(`~/ros2_ws`)가 덮어쓰지만, `motoman_description`(xacro)은 overlay 에 없으면 위 변경이 팀원 실행에도 적용된다. 팀원에게 확인할 것.
- **되돌리기**:
  ```bash

  cp $D/motoman_bringup/config/controllers.yaml.bak_250hz_20261118 $D/motoman_bringup/config/controllers.yaml
  cp $D/motoman_description/robots/ros2_control.xacro.bak_250hz_20261118 $D/motoman_description/robots/ros2_control.xacro
  cd $D && colcon build --packages-select motoman_bringup motoman_description
  ```

### (3) 브랜치에 들어 있는 것 (요약)
- `third_party/grasp_and_throw/`: 팀원 폴더를 **수정 없이** 넣었다.
- `cycle_throw/`: `GP8_MODE=cycle` 모드.
  - 플래너는 별도 프로세스로 돈다.
  - 앱은 인식 큐의 물체를 플래너에 넘기고, 받은 2 ms 명령을 Python 에서 `_emit_sample` 로 직접 보낸다.
  - 늦은 명령 조각이나 한 주기 증분 한계를 넘는 샘플이 나오면 보내지 않고 그 자리에서 정지한다.
- `GP8_STREAM_HZ=250|500`(기본 250): 500 은 드라이버가 500 Hz 일 때만 쓴다. 실기 cycle 모드는 500 을 요구한다.
- MuJoCo twin 에 컨트롤러 필터 모델(`GP8_SIM_SERVO_FILTER=box200_80`)을 추가했다.
- 기본값(`GP8_MODE=skills`, 250 Hz)이면 기존 skill 데모 동작은 바뀌지 않는다.

## 3. 팀원의 실기 구조 (조사 결과, robot6 `~ryugaeun/rge_jc/how_to_run_rt.md`)
- 계획은 **robot6**(`rt_run_hw.py`)에서 돈다. 이 PC 는 `~ryugaeun/rge_jc/run_robot_rt.sh` + `hw/hw_world.py`(다리)로 명령만 내보낸다.
- 통신: 이 PC 가 robot6 로 ssh 터널을 연다.
  - 제어: JSON RPC (시계 동기화, 상태)
  - 명령: 샘플마다 double 7 개 = 관절 6 + 틱 시각. 조각 단위로 미리 보낸다
  - 물체: HTTP NDJSON
- 명령은 **SampleBufferController**(팀원 overlay 에만 있음)의 버퍼에 틱 번호로 쓰이고, 컨트롤러 틱(2 ms)마다 재생된다. 석션 OFF 는 릴리즈 0.2 s 전.
- 최근 실기 실행: 11-18 17:35–17:58. 17:58 실행은 접촉 17 회, 늦은 조각 0. 기록으로 보아 500 Hz 로 판단된다(설정 파일은 권한이 없어 직접 확인하지 못했다).

## 4. 남은 일
1. 팀원에게 확인: `ros2 param get /controller_manager update_rate`, overlay 에 `motoman_description` 이 있는지.
2. 우리 cycle 모드를 팀원 방식으로 바꿀지 결정. 지금은 Python 이 2 ms 마다 직접 송신하는데, 팀원은 이 방식의 흔들림(CODE 112) 때문에 컨트롤러 버퍼로 옮겼다.
   그 전까지 데모는 팀원 파이프라인(`run_robot_rt.sh`)을 쓰는 것이 안전하다.
3. 실기에서 쓸 때 `GP8_CYCLE_RELEASE_LEAD=0.2`(팀원 실기 값, 브랜치 기본은 0).
4. 브랜치 GitHub push (노트북에서).
5. 이 PC 에서 `GP8_MODE=cycle` 을 단독으로 실행하지 말 것 — 플래너가 느려 첫 늦은 조각에서 정지한다.
